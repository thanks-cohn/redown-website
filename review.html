PRODUCT REVIEW / EXPLANATION

Review REDOWN.

Transparent product purpose, supported cloud connections, permission boundaries and an outline of the demonstration we will provide when Google Drive is ready.

Purpose and audience

REDOWN is a user-directed cloud transfer and file organization browser extension. It helps creators, students and developers move supported files from websites into cloud storage they control. Its present main destination is Cloudflare R2, which has an S3-compatible API. A Cloudflare Worker supports eligible direct remote transfers. The extension also includes a browser-based explorer for its authorized cloud locations.

What REDOWN is not

REDOWN does not grant cloud storage space, cannot guarantee every website supports remote fetching, and is not a general permission to copy copyrighted or unauthorized material. Its direct-to-cloud behavior is conditional on supported transfer paths. Local uploads and browser-assisted download paths may involve the device.

Proposed Google Drive access

REDOWN intends to request https://www.googleapis.com/auth/drive.file for a least-privilege workflow involving files created by or explicitly opened for REDOWN. The requested scope is for operations that the user initiates, such as saving a selected file into Google Drive and then confirming its location. The released implementation and exact OAuth consent text must be checked before this page is used as verification evidence.

Demonstration plan

When the integration is functional, a real screen recording should demonstrate the following with a disposable test account and harmless sample assets. The illustrations on the homepage gallery are visual concepts, not a substitute for a functioning OAuth demonstration.

01 / Start in the installed extension

Show REDOWN and the Chrome extension identity from the actual build intended for review.

02 / Click “Connect Google Drive”

Show Google's genuine sign-in and consent flow, including the exact scope being requested.

03 / Approve with the test account

Authenticate with a test user in Google OAuth Testing mode. Do not record or disclose credentials.

04 / Transfer a test file

Select a permitted public sample and save it into Google Drive using the tested product workflow.

05 / Verify the result

Open Google Drive and show that the expected file was created, then demonstrate the app's access/disconnect behavior.
